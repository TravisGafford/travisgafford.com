# travisgafford.com

A static website. No frameworks, no dependencies, nothing to install.

The whole site is generated by one Node script (`tools/build.mjs`) from the content
files. GitHub builds and publishes it automatically every time you save a change.

---

## The 90% case: changing words on the site

1. Go to your repo on **github.com**
2. Open `content/site.mjs`
3. Click the **pencil icon** (top right of the file)
4. Change the text between the quote marks
5. Scroll down, click **Commit changes**

The site updates itself in about a minute.

That one file holds your bio, job title, stats, the work items, the consulting
services, the brand list, and your social links. It has comments explaining each
section.

---

## Writing a blog post

1. Go to the `content/posts` folder on github.com
2. Click **Add file → Create new file**
3. Name it like `2026-08-15-my-post-title.md`
4. Paste this in and edit:

```
---
title: The title of the post
date: 2026-08-15
summary: One or two sentences. This shows on the blog index and in search results.
draft: false
---

Write here. A blank line starts a new paragraph.

## A subheading

- a bullet
- another bullet

**Bold text** and *italic text* and [a link](https://example.com).
```

5. Click **Commit changes**

The post appears at `/blog/my-post-title/`, gets added to the blog index, the RSS
feed, and the sitemap automatically. The date prefix in the filename is just for
keeping the folder tidy — it is stripped out of the URL.

Set `draft: true` to keep a post from publishing.

---

## Adding a photo

1. Upload the image to `public/assets/img/` on github.com
2. Reference it in a post as `![description of the photo](/assets/img/yourfile.jpg)`

Always write a real description in the square brackets. It is what screen readers
announce and what search engines read.

## Folder map

```
content/site.mjs        All the words on the non-blog pages. Edit this one.
content/posts/          Blog posts, one markdown file each.
public/assets/img/      Photos.
public/assets/css/      Styling.
tools/build.mjs         The generator. Only touch this to change page structure.
tools/md.mjs            Markdown to HTML converter.
.github/workflows/      The automation that publishes the site.
_site/                  Generated output. Never edit; it is rebuilt every time.
```

## Running it on your own computer (optional)

You do not need this — GitHub does the build for you. But if you want to preview
locally, install [Node.js](https://nodejs.org), then:

```
node tools/build.mjs
cd _site
python -m http.server 8000
```

Open http://localhost:8000

---

## Why there are no dependencies

Most website tooling pulls in several hundred packages. Those packages get
updates, deprecations, and security advisories, and in a year or two a build that
worked fine starts failing for reasons that have nothing to do with your site.

This one uses only what Node ships with. There is no `npm install` step in the
build. The realistic failure mode over the next decade is close to zero.
